# Trade Journal AI

Trade Journal AI is an agentic trade-intelligence backend built on top of a deterministic trading analytics pipeline. It ingests raw stock order data, normalizes execution logs into paired trades, enriches them with OHLCV and intraday market context, computes P&L analytics, and then layers AI-generated reasoning on top through CrewAI and OpenAI.

The system is designed as a hybrid architecture: the quantitative layer is rule-based and reproducible, while the qualitative layer is generated by specialized agents that produce structured outputs such as `strategy`, `emotion`, `signal_timeline`, daily journal insights, and instrument-level analysis. MongoDB is used as the persistence and caching layer so expensive AI inference is not repeated on every request.

## What It Does

- builds daily, monthly, and yearly trading analytics from raw orders
- pairs execution legs into completed trades using FIFO matching per instrument
- generates AI summaries for trading behavior, trade setup classification, and post-trade instrument analysis
- caches daily reports, instrument reports, yearly P&L, and telemetry in MongoDB
- exports daily data as CSV and rich day reports as PDF
- supports trader notes via text and voice transcription
- exposes monitoring endpoints and a separate backend-monitor service for outage alerting

## AI Stack

- `CrewAI` for multi-agent orchestration
- `OpenAI` for structured reasoning and voice transcription
- `Pydantic` for schema-constrained AI output contracts
- `MongoDB` for caching AI results, reports, telemetry, and notes

The AI layer is broken into specialized roles instead of one monolithic prompt:

- `TradeTaggingCrew`: low-latency inference for `strategy` and `emotion`
- `DailyJournalCrew`: session-level smart insights
- `InstrumentAnalysisCrew`: instrument-specific signal timeline and execution review
- `PatternInsightCrew`: time-window performance interpretation

## Architecture

1. Raw stock orders are loaded from MongoDB into an in-memory runtime store.
2. The analytics layer pairs filled orders into trades and computes deterministic session metrics.
3. Nubra market-data tools fetch historical and intraday context for those instruments.
4. CrewAI orchestrates multiple specialized agents to generate structured trade intelligence.
5. Results are cached in MongoDB to reduce OpenAI latency and repeated inference cost.
6. Monitoring endpoints and a separate monitor process track route latency, LLM workflow usage, and backend availability.

## Quick Start

### 1. Create environment

Use the example file as a template:

```bash
cp .env.example .env
```

Set at least:

- `OPENAI_API_KEY`
- `MONGO_URI`
- `MONGO_DB_NAME`
- Nubra credentials if you want OHLCV/intraday enrichment

### 2. Start MongoDB

```bash
docker compose up -d mongo
```

### 3. Start the API

```bash
make run
```

### 4. Start the external backend monitor

```bash
make run-monitor
```

## Monitoring

The application includes two monitoring layers:

- in-app observability:
  - `/monitoring`
  - `/monitoring/summary`
  - `/monitoring/alerts`
- external outage monitor on port `8001`:
  - checks the main backend health endpoint
  - sends Slack alerts on downtime and recovery

This split is intentional: the in-app dashboard is useful for latency and LLM telemetry, while the separate monitor can still detect outages when the main API is completely unavailable.
